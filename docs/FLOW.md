# 評論小幫手 — 完整流程設計（v1 自用版）

> 設計日期：2026-10-01｜目標：萬家福五甲店 Google 新評論自動偵測＋AI 回覆建議＋LINE 推播＋試算表紀錄

## 一、系統架構

```
Google 地圖（評論來源）
   │ browser 讀取（每 2 小時）
   ▼
助理 cron（偵測＋AI＋協調）
   ├─→ POST /api/ingest ──→ D1（唯一真相來源，去重）
   ├─→ 產生 AI 回覆建議 ──→ POST /api/suggest ──→ D1
   ├─→ POST /api/notify ──→ Worker ──→ LINE 群組推播
   ├─→ 試算表 append 一列（流水帳）
   └─→ WhatsApp 推播給榮德（備援）
              │
              ▼
人工：複製建議 → 到 Google 商家後台回覆 → 網頁後台按「標記已回覆」
```

**設計原則**：D1 是唯一的真相來源；LINE／試算表／WhatsApp 只是「呈現」。
將來販售版只要把「助理 cron 偵測」換成「Google 官方 API 輪詢」，其他全部不用動。

## 二、完整流程（正常情況）

| 步驟 | 誰做 | 做什麼 | 失敗時 |
|---|---|---|---|
| 1. 偵測 | 助理 cron（08:00–22:00，每 2h） | browser 開地圖連結，讀最新 10 則 | browser 失敗→重試 1 次，仍失敗→WhatsApp 告訴榮德 |
| 2. 入庫 | Worker /api/ingest | 去重（作者＋星數＋內文前40字），回傳新增 | DB 未綁定→回 500，助理告警 |
| 3. AI 建議 | 助理 | 依星級規則產生繁體中文回覆草稿 | — |
| 4. 存建議 | Worker /api/suggest | 寫入 D1 | — |
| 5. LINE 推播 | Worker /api/notify | 推到群組：評論＋AI 建議；1–2 星加 ⚠️ | 無群組 ID→回 no_line_target，改只走 WhatsApp |
| 6. 試算表 | 助理 | append：時間｜評論者｜星數｜內容｜AI建議｜狀態 | API 失敗→記下來下輪補 |
| 7. WhatsApp | 助理 | 丟給榮德同一份（備援，他個人看） | — |
| 8. 人工回覆 | 榮德／店經理 | 複製（可改）→ Google 商家後台貼上 | — |
| 9. 結案 | 榮德 | 網頁後台按「標記已回覆」 | — |

## 三、AI 回覆建議規則

- 5 星無文字：簡短感謝＋歡迎再來（50 字內）
- 4–5 星有文字：針對提到的點具體回應＋感謝
- 3 星：感謝＋針對缺點說明會改進
- 1–2 星：誠懇致歉、不辯解、說明檢討改進、留客服專線 0800-567-788，邀私下聯繫
- 抱怨改名：溫和說明品牌更新是為了更好服務，感謝長期支持
- 一律繁體中文、150 字內、結尾署名（設定頁可改）
- **鐵律：1–2 星只給建議，絕不自動發佈，一定要人工審核**

## 四、例外流程

- **偵測到 1–2 星**：LINE 訊息開頭加 ⚠️「低分評論，請人工審核後再回覆！」
- **連續 2 次偵測失敗**：WhatsApp 通知榮德「偵測異常」，不靜默失敗
- **重複推播**：ingest 去重擋掉；notify 只推本次 ingest 新增的 ID
- **Google 改版面 browser 讀不到**：助理修 selector，修不好就先改回每日人工檢查並告知

## 五、資料表

- `reviews`：評論本體（review_key 去重）
- `suggestions`：AI 建議（一則一筆）
- `settings`：店名／電話／語氣／署名
- `line_sources`：LINE 推播目標（webhook 自動記錄）
